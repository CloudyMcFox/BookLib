# Security Policy

## Supported versions

Security fixes are applied to the latest release and the `main` branch.
Self-hosted installations should update to the latest release before reporting
an issue that may already be resolved.

## Reporting a vulnerability

Do not open a public issue for a suspected vulnerability.

Use GitHub's **Report a vulnerability** option on the repository's Security
page. Include:

- The affected version or commit
- The deployment configuration needed to reproduce the issue
- Reproduction steps or a minimal proof of concept
- The potential impact
- Any suggested remediation

Do not include real access tokens, passwords, API keys, database contents, or
personal borrower information. Replace sensitive values with clearly marked
examples.

You should receive an acknowledgment through the private advisory within seven
days. Please allow time for a fix before publishing details.
